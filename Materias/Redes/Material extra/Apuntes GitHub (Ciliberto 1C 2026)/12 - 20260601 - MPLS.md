## Clase 12 - MPLS

### Introducción a MPLS

MPLS es una tecnología de transmisión de datos y transporte diseñada para combinar la **velocidad del conmutado de etiquetas** (típico de la Capa 2) con la capacidad de **toma de decisiones del enrutamiento IP** (Capa 3). Por esta razón, se considera un protocolo que opera de forma híbrida entre las **Capas 2 y 3** del modelo OSI.

### Funcionamiento y Mecanismo de Etiquetas

A diferencia del ruteo IP tradicional, donde cada router debe revisar tablas de ruteo complejas "salto por salto", MPLS utiliza un sistema de **etiquetado**:

- Al ingresar a la red, se le asigna una etiqueta al paquete que establece una ruta predeterminada.
- Los routers internos no miran la dirección IP de destino, sino únicamente la etiqueta, lo que agiliza drásticamente el reenvío de tráfico.
- Es útil para integrar protocolos antiguos (_Legacy_) como **ATM** o **Frame Relay** bajo un mismo paraguas tecnológico de forma eficiente y escalable.

### Arquitectura de la Red MPLS

La infraestructura se divide en distintos roles de routers y áreas:

- **LER (Label Edge Router):** Es el router de borde que se encarga de asignar la etiqueta inicial al paquete cuando entra al dominio MPLS.
- **LSR (Label Switch Router):** Es el router de núcleo (_core_) que conmuta los paquetes basándose exclusivamente en la etiqueta recibida.
- **PE (Provider Edge):** Router de cabecera del proveedor que concentra a múltiples clientes.
- **CE (Customer Edge):** El router que se encuentra físicamente en las instalaciones del cliente final.

### Estructura de la Cabecera MPLS (Shim Header)

La cabecera tiene una longitud total de **32 bits (4 bytes)** y se inserta entre la cabecera de Capa 2 y la de Capa 3. Se compone de cuatro campos:

1. **Label (20 bits):** El identificador del camino o etiqueta propiamente dicha.
2. **Exp/CoS (3 bits):** Bits experimentales utilizados para definir el nivel de **Calidad de Servicio (QoS)** (priorización de voz, video o datos críticos).
3. **S (Stack - 1 bit):** Indica si es la última etiqueta de la "pila" de etiquetas.
4. **TTL (8 bits):** El tiempo de vida (_Time to Live_) del paquete.

### Proceso de transporte de datos con MPLS

1. **Origen en el Cliente (CE):** El proceso comienza cuando el router del cliente, denominado **CE (Customer Edge)**, envía un paquete de datos (normalmente un paquete IP) hacia la red del proveedor.

2. **Ingreso a la red MPLS (LER / PE):** El paquete llega al router de borde del proveedor, conocido como **LER (Label Edge Router)** o **PE (Provider Edge)**. Este router realiza las siguientes funciones:
    - Analiza el paquete y determina a qué **FEC (Forwarding Equivalence Class)** pertenece (por ejemplo, según su destino o tipo de servicio).
    - **Asignación de etiqueta (Label Push):** Le añade una etiqueta de 32 bits (4 bytes) entre el encabezado de Capa 2 y el de Capa 3.

3. **Tránsito por el Núcleo (LSR):** El paquete viaja a través de los routers internos de la red, llamados **LSR (Label Switch Router)** o routers **P**. En este tramo:
    - Los routers **no revisan la dirección IP** de destino.
    - Solo miran la etiqueta, consultan su tabla de reenvío (**LFIB**, *Label Forwarding Information Base*) y realizan un **intercambio de etiqueta (Label Swap)**, reemplazando la etiqueta actual por una nueva para el siguiente salto.

4. **Preparación para la salida (PHP):** Antes de llegar al final, el último router de núcleo (LSR) realiza una operación llamada **Penultimate Hop Popping (PHP)**.
    - En este paso, se **quita la etiqueta (Pop)** del paquete para que el router de salida no tenga que procesarla innecesariamente.

5. **Salida de la red y destino final (PE a CE):** El paquete llega al router PE de salida ya como un paquete IP original (o se le quita la última etiqueta allí) y este lo entrega al router **CE de destino** en las instalaciones del cliente.

En resumen, el flujo es: **CE** (envío) → **PE/LER** (etiquetado/Push) → **LSR** (conmutación/Swap) → **PE/LER** (desetiquetado/Pop) → **CE** (recepción).

### VRFs (Virtual Router and Forwarding)

- **Aislamiento de Clientes:** Las VRF permiten que un mismo router físico (normalmente el **PE - Provider Edge**) funcione como si fuera múltiples routers independientes. Cada cliente tiene su propia instancia de ruteo virtual, lo que significa que el tráfico y las tablas de direcciones de un cliente están completamente separados de los de otros,.
- **Tablas de Enrutamiento Independientes:** Dentro de una VRF se asocian todas las tablas de etiquetado y direccionamiento de un cliente en particular. Por ejemplo, la VRF del "Cliente X" contiene solo sus rutas, y estas no son visibles para la VRF del "Cliente Y".
- **Independencia de Direccionamiento:** Gracias a esta separación lógica, diferentes clientes pueden utilizar los mismos rangos de direcciones IP (direcciones privadas solapadas) sin que existan conflictos, ya que cada uno opera en su propio entorno de red virtual,.
- **Nubes Virtuales:** El uso de VRFs permite establecer virtualmente "nubes" o "sub-nubes" para distintos clientes dentro de una misma infraestructura de backbone MPLS,.
- **Escalabilidad Operativa:** Para un proveedor de servicios (ISP), sería inviable dedicar un router físico a cada cliente. Las VRFs permiten concentrar a miles de clientes en equipos de alta capacidad, agregando "capas" de configuración lógica para separar sus entornos.

En resumen, las VRF actúan como **instancias de ruteo virtual** que segmentan la red del proveedor para que múltiples empresas convivan en la misma infraestructura física de forma segura e independiente,.

### Servicios de VPN en MPLS

MPLS es la base para crear **Redes Privadas Virtuales (VPN)** seguras sobre una infraestructura pública. Existen dos tipos principales:

- **L3VPN (Layer 3 VPN):** El ruteo se maneja a nivel IP. Utiliza **VRFs (Virtual Routing and Forwarding)**, que son instancias de ruteo virtual que aíslan el tráfico de un cliente de otros entornos de red, garantizando privacidad y seguridad.
- **L2VPN (Layer 2 VPN):** Permite transportar tramas de Capa 2 (Ethernet, Frame Relay) sin realizar enrutamiento IP. Funciona como una extensión física del cable (un túnel o _pseudowire_) entre dos sitios, manteniendo la misma LAN o VLAN de extremo a extremo.

### Ventajas Principales de MPLS

- **Velocidad:** La conmutación por etiquetas es más rápida que el procesamiento de ruteo IP tradicional.
- **Calidad de Servicio (QoS):** Permite priorizar tráficos sensibles a la latencia, como la voz sobre IP o el streaming multimedia.
- **Ingeniería de Tráfico:** Facilita la distribución de cargas para evitar cuellos de botella y congestiones en la red del operador.
- **Escalabilidad:** Es sencillo ampliar la red para miles de sucursales o clientes manteniendo un control centralizado.
- **Soporte Multiprotocolo:** Puede transportar IPv4, IPv6, ATM y Frame Relay indistintamente.
